# 구조와 데이터 계약

[README로 돌아가기](../README.md)

ControlFlow AI는 Python 표준 라이브러리 HTTP 서버, 단일 HTML UI, 로컬 OCR·LLM으로 구성됩니다. 데이터의 출처를 확인하지 못하면 통제 판정을 보류하는 구조입니다.

## 1. 문서 생성과 읽기

`make_evidence.py`는 평가용 fixture로 PDF 6건을 생성합니다. AP001·003·005는 텍스트층이 있는 PDF입니다. AP002·004·006은 생성한 페이지를 이미지로 렌더링해 새 PDF에 넣으므로 텍스트 추출 결과가 비어 있습니다. 생성 시 이 구분을 assertion으로 확인합니다.

`read_evidence()`는 텍스트층이 있으면 PyMuPDF span 좌표로 읽기 순서를 정리합니다. 텍스트층이 없으면 페이지를 렌더링하고 RapidOCR을 호출해 셀의 좌표·문자열·신뢰도를 저장합니다. OCR 신뢰도는 인식된 셀 점수의 평균이며 필드 정답률은 아닙니다.

## 2. 실제 모델 추출과 독립 검증

`infer()`는 `http://127.0.0.1:11435/api/chat`의 `qwen2.5:1.5b`를 호출합니다. 현재 설정은 temperature 0, seed 42, context 4096, CPU 추론입니다. 설정을 고정해도 환경·모델 변경에 대한 동일 출력 보장은 없습니다.

추출 프롬프트에는 원문, 9개 필드의 라벨, 관련 없는 형식 예시와 JSON Schema가 들어갑니다. 정답 fixture는 전달하지 않습니다. 각 필드의 계약은 다음과 같습니다.

```json
{
  "invoice_amount": {
    "value": "1100.00",
    "quote": "Invoice total: 1100.00"
  }
}
```

이 예시는 AP002의 한 필드 형식을 보여 줍니다. 실제 모델 호출에서는 9개 필드 모두를 요구합니다. 누락 필드는 `value: null`, `quote: ""`입니다.

`ground_fields()`는 다음을 대조합니다.

1. 필요한 필드 집합과 각 객체의 키가 올바른가.
2. 인용문이 공백을 정규화한 원문에 그대로 존재하는가.
3. 인용문에 해당 필드 라벨과 전체 값이 함께 있는가.
4. 원문의 라벨이 중복되거나 공급자 메모 안에 모호하게 들어 있지 않은가.

잘못된 출력은 모델이 내놓은 값과 사유를 남기고 `supported: false`로 처리합니다. 정규식은 모델의 값을 사후 검증합니다. 원문에서 대신 정답을 추출해 모델 결과를 덮어쓰지 않습니다. 재시도 조건에 해당하면 같은 원문과 검증 실패 사유로 **실제 모델 호출을 한 번 더** 수행하고 두 원응답을 보존합니다.

AP006에는 청구금액을 바꾸라는 공급자 메모와 누락된 승인자 필드가 있습니다. 이는 제한된 프롬프트 인젝션·누락 사례이며 모든 공격에 대한 안전성 검증은 아닙니다.

## 3. 통제 계산과 제한된 초안

통제는 검증된 값으로 계산합니다. 금액은 Decimal, 날짜는 ISO 날짜, ID는 제한된 문자 집합으로 확인합니다. C03은 전체 6건에서 중복을 검사합니다. 한 건이라도 거래처·송장 키의 원문 근거가 부족하면 모집단의 유일성을 확인할 수 없으므로 중복 판정은 미확인이 될 수 있습니다.

초안 입력은 해당 문서 페이지, C01~C04의 절차, 계산한 통제 결과입니다. 이것은 **RCM ID와 문서 ID를 통한 결정론적 문맥 선택**이며 벡터 DB·임베딩 검색을 사용하지 않습니다.

모델은 계산 결과를 아래 형식으로 반환합니다.

```text
C01=pass; C02=exception; C03=pass; C04=pass. Human review required.
```

검증기는 전체 문장이 계산한 상태와 정확히 같은지, 문서 페이지와 모든 RCM ID가 포함됐는지 확인합니다. 자유로운 설명을 생성·검증하는 기능은 현재 범위에 없습니다. 판단 사유는 사람이 원문을 보고 작성합니다.

## 4. 검토 지문과 내보내기

`source_fingerprint()`는 PDF, 모델 digest, 추출 schema, 프롬프트, RCM, `engine.py`, `make_evidence.py`를 묶습니다. `result_fingerprint()`는 원문·필드·통제 결과·초안 등 결과 내용을 묶습니다. 검토와 내보내기 요청은 현재 실행 ID 및 두 지문을 검사합니다.

사람의 검토에는 이름, 결론, 8자 이상의 사유가 필요합니다. 이름 입력은 사용자 인증을 대신하지 않습니다. 검토 이력은 버전과 함께 JSONL에 추가하며 현재 결과도 저장합니다.

| 모델·규칙 상태 | 의미 |
|---|---|
| `pass` | 필요한 필드의 근거와 타입이 검증됐고 해당 조건을 충족 |
| `exception` | 필요한 근거가 검증됐고 해당 조건을 위반 |
| `unknown` | 필수값·근거·타입 또는 모집단 정보가 부족해 판정 보류 |

| 사람 검토 결론 | 서버 조건 |
|---|---|
| `cleared` | 모든 통제가 `pass`일 때만 저장 가능 |
| `confirmed_exception` | 하나 이상의 `exception`이 있어야 저장 가능 |
| `request_info` | 추가 증빙을 요청한 상태로 내보내기 차단 |

선택 범위 안에 미검토, 미완료 요청, `unknown`, 원문 근거 없는 필드, 미검증 초안, 지문 불일치가 있으면 내보내기를 차단합니다. 예외가 확인된 문서는 조건을 충족하면 예외 상태를 보존한 채 내보낼 수 있습니다. 결과는 합성 검토 조서 JSON이며 감사 의견을 생성하지 않습니다.

부분집합 내보내기는 `document_ids`를 명시합니다. 출력에는 포함 ID, 전체 모집단 실행 ID와 문서 수가 기록됩니다. C03 검사의 전체 모집단 기준을 부분집합의 유일성 검사로 바꾸지 않습니다.

## 5. API와 파일

| 요청 | 동작 |
|---|---|
| `GET /api/state` | 실행 상태, 마지막 결과, 모델 연결과 원문 지문 대조 |
| `POST /api/run` · `{}` | 실제 추론 작업 시작. `202`와 job ID 반환 |
| `POST /api/review` | 현재 실행의 문서 검토 저장 |
| `POST /api/export` | 검증 조건을 확인한 전체 또는 선택 범위 생성 |
| `GET /api/evidence/AP001.pdf` ~ `AP006.pdf` | 허용된 합성 원본 PDF |
| `GET /api/export/latest.json` | 마지막으로 생성한 조서 JSON |

검토 요청:

```json
{
  "run_id": "<현재 실행 ID>",
  "document_id": "AP002",
  "decision": "confirmed_exception",
  "reviewer": "Demo reviewer",
  "note": "합성 원문에서 청구 1100.00과 발주·입고 1000.00의 차이를 확인했습니다."
}
```

부분집합 내보내기 요청:

```json
{
  "run_id": "<현재 실행 ID>",
  "reviewer": "Demo reviewer",
  "attestation": true,
  "document_ids": ["AP002"]
}
```

이 요청도 서버 조건을 통과해야 성공합니다. 검토 이름이나 확인 체크만으로 검증을 우회하지 않습니다.

각 실행 폴더에는 `*.source.json`, `*.extract.raw.json`, 필요 시 `*.extract.retry1.raw.json`, `*.retrieval.json`, `*.draft.raw.json`, `manifest.json`, `result.json`, 검토 시 `review_history.jsonl`이 저장됩니다. 실패한 실행은 `failure.json`을 남깁니다. 원응답에 모델 이름, 토큰 수, 실행 시간과 프롬프트 해시를 기록합니다. 오래된 결과와 새 검증 결과를 구분해 읽어야 합니다.

## 6. ITGC 확장과의 경계

ITGC 확장은 한국어 텍스트형 PDF에서 정확한 라벨과 직접 인용을 읽고, 미리 생성한 `source-data.js`를 브라우저에서 사용합니다. 사용자가 바꾸는 입력은 원본과 분리한 시뮬레이션 가정입니다. 두 규칙은 계정 비활성 여부와 데모 허용시간 내 회수 여부이며, 시간 증빙 누락은 미확인으로 남깁니다.

메인 앱의 Python HTTP 서버는 확장 폴더를 제공하지 않습니다. 확장 HTML을 별도로 열어야 하며, 메인 실행·검토 지문 또는 조서에 자동 통합되지는 않습니다.
