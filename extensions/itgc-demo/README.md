# 퇴사자 계정 회수 · 한국어 IT 일반통제 실험

퇴사 후 계정이 계속 활성 상태이거나 회수 기한을 넘겼다면 어떤 통제 예외가 생길까요? 한국어 합성 증빙에서 읽은 기준값과 사용자가 바꾼 조건을 나란히 비교하는 작은 업무 시뮬레이션입니다.

**브라우저에서 `index.html`을 열면 바로 실행됩니다.** 서버·로그인·Ollama 없이 동작합니다. 이 확장 데모는 텍스트 PDF 파싱과 규칙 계산을 사용하며, 메인 프로젝트와 달리 OCR·LLM을 호출하지 않습니다.

## 직접 바꿔보기

1. **기준 시나리오:** 회수 지연 12시간, 계정 비활성, 시각 증빙 완전 → I01/I02 모두 통과.
2. **지연 + 활성:** 48시간 지연, 계정 활성 → 두 통제 모두 예외.
3. **시각 증빙 누락:** 회수 기한 판정은 미확인으로 남습니다.
4. **회수 지연 -1:** 입력 오류를 표시하고 계산·판정을 보류합니다.
5. **초기화:** 원본 기준의 12시간·비활성·완전 증빙으로 돌아갑니다.

왼쪽 원본 증빙은 변경되지 않습니다. 오른쪽 값과 계산 시각은 시뮬레이션 가정입니다. 허용시간 기본 24시간은 데모 가정이며 법률이나 특정 회사의 정책이 아닙니다.

## 입력 → 규칙 → 상태 → 결과

| 단계 | 실제 동작 |
|---|---|
| 원본 | `퇴사자_계정_회수_확인서.pdf`의 한국어 텍스트층 |
| 추출 | Employee ID·Account ID·퇴사 시각·회수 시각·계정 상태 5개 라벨과 직접 인용 |
| 원문 대조 | `extracted.json`에 원문·페이지·SHA-256·라벨별 인용 저장 |
| I01 | 활성 계정은 예외, 비활성은 통과 |
| I02 | 증빙이 완전하고 지연시간 ≤ 허용시간이면 통과; 초과는 예외; 증빙 누락은 미확인 |
| 결과 | 시간·계정 상태·통제 상태와 기준/현재 비교표를 즉시 갱신 |

## 검증 및 증빙 재생성

저장소 루트에서 Node.js로 계산·인용 검증을 실행합니다. 외부 패키지를 설치하지 않습니다.

```sh
node extensions/itgc-demo/verify.cjs
```

8개 확인을 실행하고 이 폴더의 `before-after-results.json` 및 `verification/checks.json`을 기록합니다. `verification/`은 Git에 포함되지 않습니다. 경계값 24/25시간, 활성 계정, 증빙 누락, 음수, 초기화, PDF 해시와 인용을 확인합니다.

증빙은 이미 포함되어 있습니다. 재생성은 **Windows의 맑은고딕(`C:/Windows/Fonts/malgun.ttf`)**과 메인 프로젝트의 Python 의존성이 필요합니다.

```sh
python -X utf8 extensions/itgc-demo/build_evidence.py
node extensions/itgc-demo/verify.cjs
```

다른 운영체제에서 재생성하려면 `build_evidence.py`의 한국어 폰트 경로를 해당 환경의 폰트로 지정해야 합니다. 브라우저 데모 자체는 Windows 전용이 아닙니다.

## 범위와 한계

한국어 **텍스트형** 합성 PDF의 라벨·인용 추출과 I01/I02 계산을 검증합니다. 스캔 문서 OCR, 한국어 LLM 정확도, 임의 양식 일반화, 실제 회사의 운영 효과는 검증하지 않았습니다. 실제 직원·고객·ERP 자료를 포함하지 않으며, 실제 감사의견이나 고객 컨설팅 수행 사례가 아닙니다.

메인 서비스 설명과 실행 방법은 [루트 README](../../README.md)를 참고하세요.
